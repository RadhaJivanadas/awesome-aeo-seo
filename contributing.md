# Contributing

Contributions welcome. Follow the [sindresorhus awesome contributing guidelines](https://github.com/sindresorhus/awesome/blob/main/contributing.md) alongside the requirements below.

## Submission Format

```
- [Title](URL) - Description starting with an uppercase letter, ending with a period.
```

## Requirements

- **Working URL** — every entry must resolve to the described resource; verify before submitting.
- **No SaaS vendor or agency links** — you may name vendors in descriptions but do not link to them; open-source repository URLs and `discoveredlabs.com/tools/*` URLs are allowed.
- **One sentence** — descriptions are a single sentence: genuinely informative about what the resource tells you, not a restatement of what it is.
- **Expert audience** — write for engineers and growth marketers who do not need basic concepts defined.
- **Evidence, not opinion** — papers and empirical studies require a methodology note in the description (venue, sample size, or key experimental design detail).
- **Open-source tools** — must have a public GitHub repository with runnable code; no closed-beta or invite-only tools.
- **Research gaps** — if you identify a topic where no quality resource exists, add it to the Known Research Gaps section rather than submitting a weaker substitute.

Open a pull request on a branch named `add/<short-description>` with a one-line explanation of what you are adding and why it belongs in this list.
